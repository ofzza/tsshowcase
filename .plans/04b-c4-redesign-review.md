### Questions (for the user)

- **Q1 (ok, option a; I1, F10):** `inScope(path)` is true iff the path is in the tree as an in-scope directory or file (nonexistent, ignored and connector paths false; D170's nonexistent-vs-out-of-scope distinction stays `RepoFiles.exists`'s); `packageOf(path)` is the deepest package in `RepoScan.packages` containing the path, lexically (so out-of-scope paths work), `undefined` outside every package and inside skipped or ignored nested packages (nonexistent, D103); both pure lookups over the snapshot; tests for each case. Applied to C4 §2, §12. Rejected: (b) a lexical `inScope` (true for nonexistent paths); (c) `packageOf` returning the parent for paths in skipped/ignored nested packages (attributes nonexistent content to the parent).
- **Q2 (ok, option a; I2):** the package directory is matched as `.`, covered by the entries `.` and `**` (picomatch's `**` alone wouldn't); `validateScope()` (called by C6) normalises: leading `./` removed, trailing `/` stripped, repeated `/` collapsed, `''`/`./` → `.`, backslashes rejected with a hint (picomatch's escape character), duplicates merged silently; the unmatched warning names the entry as first written; tests. Applied to C4 §5, §12 and the C6 recorded point. Rejected: (b) `**` not covering the package directory (users would need `['.', '**']`); (c) no normalisation (spurious unmatched warnings).
- **Q3 (ok, option a; I4, F3):** J2 generalised: a detected package whose directory doesn't exist under C4 §4 from any source (ignore files, config `ignore`, the output marker or `outDir`, `skip`) isn't a package (info line). C4 exports `packageExists(workspace, dir, { ignore, outDir, skippedPackages })` (reads only the ignore files on the root-to-package path); C6 asks it before loading package configs, so a left-out package's config is never loaded or validated and its `scope` never reaches the scan (a package's own `skip` still needs its config). Applied to C4 §2, §3 pointer, §4, §10, §12 and the C6 recorded point. Rejected: (b) load every package config and drop afterwards (a broken config inside an ignored package could break the run); (c) swallow their config errors after the scan (more complex). The user asked what the output marker is (explained: `<outDir>/.tsshowcase-output.json`, written by `build`, a hard ignore, D101/D103).
- **Q4 (ok, option a; I5):** a package detected through its readable manifest whose directory can't be listed is kept: manifest read as usual (`scan/invalid-manifest` on failure), empty tree, empty home, `scan/unreadable` naming the package directory on its root; a package directory (or a directory on the path to it) that can't be read at all is never detected and raises nothing (documented); tests with a mocked `fs`. Applied to C4 §6, §12. Rejected: (b) drop an unlistable package (silently disappears); (c) a thrown error (one permission problem stops every action).
- **Q5 (ok, option a; I6):** a matched package directory that is a symbolic link isn't a package: skipped by detection (no link following, or an `lstat` check) with an info line naming the link; consistent with M10; documented; tested with a link created at test time. Applied to C4 §3, §12. Rejected: (b) walk it with a real-path boundary check (cycle and boundary handling, link paths vs real files); (c) a package with an empty tree (a package that can never have content).
- **Q6 (ok, option a; I11):** a workspace that yields no package prints one warning per scan (`logger.warn`), naming the declared globs and how many matches were left out as ignored, skipped or symlinked; not an issue (G5: the run's setup, not the repository's content); tested. Applied to C4 §10, §12. Rejected: (b) a `scan/no-packages` issue (a new rule id for a settings matter); (c) an info line (easy to miss); (d) nothing.

- **B (ok, option a):** the Vitest runner (C7) matches `vitest.config.*`, `vite.config.*` and the workspace files exactly as Vitest looks them up (a tool's own names), so it never runs a file Vitest wouldn't choose. Rejected: (b) any case with an error.
