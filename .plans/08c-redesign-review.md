# Redesign review triage (`08b-representation-redesign.md`)

> Three fresh-eyes reviews of the approved redesign (2026-10-19), run in parallel by clean-context agents: **T** = targeting/clarity (started from 08b alone, read what it needed; 14 findings), **I** = issues and gaps with full context (22 findings), **K** = comparison with the original design, walkthroughs and confidence. Merged below as X1–X13 (decisions) and Y1–Y16 (clarifications). Status: **resolved** (2026-10-20): every X item discussed with the user one by one (outcomes below); group Y applied; all folded into `08b` revision 2, which awaits the user's review.

## Overall verdicts

- **T:** clear about *what the redesign is*; only partly clear about *what it replaces* (no per-decision verdicts for D149–D159, D155 not mentioned, runner-ownership decisions and U16 overridden silently, no "untouched" list).
- **K:** real improvements (the unit/group tangle and claim machinery gone; one CLI-owned check rule; simpler data; `--strict` decided; per-package scope). Confidence: **medium** that it is implementable as stated; **low to medium** that it works on real repos without much configuration. The walkthroughs (a stdblox-like library, a workspace, a pure-TS library, this repo) fail in common layouts: a sibling `Button.types.ts` makes `README.md` weak; `__tests__/`/`test/` never satisfy tests; a root-level library's README can't document its symbols; nesting and menu levels flatten; AGENTS.md/CLAUDE.md become home docs on the dogfood site.
- **I:** the "what exists / checked / presented" split resolves 08a group A coherently; gaps are in test ownership, defaults for common layouts, pipeline order, links and headings, ids, and several unstated semantics.

## Group X: decisions for the user

| X1 | T1, I1, K | **Test files: who lists them, and repos without a runner.** The CLI asking a runner contradicts D34/D42/D74 (the CLI never calls a runner; the module loads it) and D148 (the CLI can't read `moduleOptions.testRunner`). Only Vitest ships: Jest, Mocha or `node:test` repos would have no test discovery at all, so every function/class/component/hook fails "missing tests". Per-package Vitest instances make `check` slower (~1 s each, D132). | The **module** enriches test files during analysis (it already selects the runner): through an optional runner method `listTestFiles` via `ctx.loadTestRunner`, keeping D34. **Fallback** when no runner is detected or it has no `listTestFiles`: a default pattern (`*.{test,spec}.{ts,tsx,mts,cts,js,jsx,mjs,cjs}`, `*.test-d.ts`), with one info line. |
| X2 | I2, K (walkthroughs A, B, D) | **Directory READMEs and multi-file directories.** With two exporting files in a directory (`Button.tsx` + `Button.types.ts`, the headless split, `-api` units split over files, a JSON schema plus its sidecar), the single-file rule fails: `README.md` turns weak and every symbol misses docs. | X3 | I2, K | **Tests in `__tests__/` or a `test/` tree** are never strongly associated (C8 round 1 accepted `__tests__/`). | Name matching also looks in a sibling `__tests__/` directory (`__tests__/Button.test.tsx` → `Button.tsx`). Mirrored `test/` trees need `paths` (documented). |
| X4 | I2, K (walkthroughs B, C) | **Root-level and single-entry libraries.** Root markdown belongs to the home only (§7.8), so a library whose only exporting file is `index.ts` or `src/index.ts` has no docs for any symbol. | When a package has exactly **one** exporting file (or collection) in total, the package README also associates with it as documentation (it stays a home doc too). | X8 | K, I17 | **No per-item opt-out** (D155 `showcase: false` gone; modules can't change requirements for well-known kinds). | X9 | I5, T8 | **Test results: who maps them, and where status lives.** The contract still has the module map results "to units" by unit dir and remap on `onAnalysisUpdate` (D42, D75, D135); there is no place for `not-run`/`unavailable` + reason, `failedRoots`, `unmapped`, `unhandledErrors`, which `--strict` needs. | The module's `runTests` returns the runner's **raw** report (plus run status); the **CLI** maps results to nodes through the test-file associations. ## Outcomes of group X (discussed one by one, 2026-10-20)

- **X1:** the CLI owns test runners entirely (candidates incl. a module's static `testRunners`, resolved from the module's package; pinning via config `testRunner`, one or several; all detecting runners used; union of listed files, overlapping files run with each runner, results per (file, runner); a failing runner reported, others used; no runner while tests are required → top-level `tests/no-runner` error, per-symbol "missing tests" suppressed, no fallback). Supersedes D3, D34, D42, D74, D75, D135 (mapping), D136.
- **X2:** three association levels: `exclusive` (name match, explicit `paths`/collection members), `strong` (a directory `README` for every exporting file in its directory; single-file leftovers), `weak` (unmatched). The check counts exclusive and strong.
- **X3:** no convention-chasing for `__tests__/`; collections may list resource members (paths, globs, within scope; exclusive; a resource may be in several collections; an exporting file in one only).
- **X4:** resolved by X2 and X3 (root READMEs stay home-only; list them explicitly).
- **X5:** nesting and menu levels stay explicit; a directory config creates a node unless all its keys are non-node keys (empty file, `{}`, `true`, display-only configs create nodes; `false` is an error; no `paths` = `paths: []`); directory links resolve in four steps (configured node; child node with that directory's README; any child node; nearest ancestor), out-of-scope → VCS host, nonexistent → broken link; README-file links match directory links; element ids prefixed with the doc's id; covered nodes may redirect.
- **X6:** upward listings **count** as check sources (the user, against Claude's "no"); the `paths: ["**"]` case is accepted.
- **X7:** every root markdown file goes to the home as a reference; the module selects; docs render lazily through the context; the CLI copies only rendered docs' assets.
- **X8:** `exempt` with glob keys, `'*'`, union of matches, unused-key warnings, a summary count.
- **X9:** `Representation.tests` = overall status/reason plus a map of runners (status, error, failedRoots, unhandledErrors, results by file); dev updates mirror it; per-node summaries derived.
- **X10:** directory configs only in scope (U16 reversed); out-of-scope references warn.
- **X11:** one issue per symbol and missing type (kept, because kinds and exemptions work per symbol).
- **X12:** unmatched tests stay weak; the module decides how to show them.
- **X13:** `--strict` with parts `check`, `tests`, `unavailable`, `unhandled`, `warnings` (bare `--strict` = the first four; repeated `--strict=<part>`, normalised in argv; config `strict: true | Part[]`); a new `--rule <id>=<severity>` flag; patterns in rule ids.
- **Principles** (added to 08b §0): stages with clear interfaces first, rules inside stages refined later; the target is the user's own, mainly new, repositories.
