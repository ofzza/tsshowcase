# C2 amendment B9 review (`chunk-02-plugin-contracts.md`, the representation redesign)

> Plan 2 of the redesign's application (08b §12, 08e E7). Status: **shape decisions H1–H7 and the agent review's outcomes settled with the user (2026-10-20)**, all applied to C2; **plan 2 approved by the user (2026-10-20)**.

## Shape decisions H1–H7 (choices B9 made where 08b and D160–D199 left a shape open; discussed one by one)

- **H1 (ok):** `DevContext.onDataUpdate` delivers `DataUpdate { representation, docs }`: every snapshot comes with its own `DocsAccess`, so a module can never render a doc against the wrong snapshot. `BuildContext.representation`/`docs` are the initial pair. Rejected: one accessor rendering against the latest snapshot (racy), `render(ref, revision)` (every call passes it; the CLI keeps old snapshots alive).
- **H2 (changed by the user):** **no `onDocsUpdate` / `DocsUpdate`** for now. Any change affecting a rendered doc, a content-only README edit included, produces a full snapshot through `onDataUpdate`, and the module renders again from its new `DocsAccess`. Claude had proposed a separate refs-only signal to avoid full snapshots on README edits; the user chose the simple option ("can always add optimisations like this later"). Changes D187 and 08b §7.10 (updated).
- **H3 (ok):** `verify` is no longer required for `check`: the CLI performs the representation check itself (D166, D174), so a module without `verify` adds no framework-specific issues and `check` prints a one-line note. D63's "a stub `verify` silently passes CI" no longer applies. `analyze` stays required.
- **H4 (ok):** the rule namespaces `represent/`, `tests/`, `config/`, `docs/`, `scan/`, `module/` are reserved for the CLI; module rules use their own namespace. Enforcement is C6's (a declared rule in a reserved namespace is a load error; an emitted one becomes a `module/error`). Rejected: a convention only; one `tss/` prefix for all CLI ids.
- **H5 (ok):** names for 08b's inline shapes: `PackageRepresentation` (the `Representation.packages` element; not `PackageNode`, the pre-redesign name, and not a node itself), `KindDescriptor` (the value of `static kinds`, like `RuleDescriptor`), `AssociationLevel` (`'primary' | 'strong' | 'weak'`, open union; the field stays `association`).
- **H6 (ok):** the config key `tests?: boolean` stays (`false` = `--no-tests`, D197); neither 08b nor D192 removed it, and it is orthogonal to `strict`.
- **H7 (ok):** the §5.11 samples use `homeDocs` (react-default's planned option, D185) instead of the removed `testRunner` option: `{ homeDocs?: string[] }` and `optionFlags = { 'home-docs': 'homeDocs', … }`; a generic illustration, C10 defines the option.

### Questions (decided by the user)

- **Q1 (ok, after the user asked what else changes):** `DataUpdate` is the part of the context that changes during a dev session: `{ representation, docs, state }`; every other `DevContext` member is fixed for the session (a config change restarts dev; theme stylesheet contents and test results have their own channels). Changes D187.
- **Q2 (ok, option A):** in `dev`, the CLI pre-copies the assets of **every** `DocRef` into `docAssetsDir` before each `onDataUpdate` (it parses every doc for `check` anyway); "only rendered docs' assets" stays a `build`-output rule. Rejected: `render()` copying assets itself (couples rendering to IO). Changes D187.
- **Q3 (ok):** `init` sees `tests.status: 'not-run'` with the new reason `'init'`; `ScaffoldContext` documents that node `issues` are empty and tests haven't run. Changes D186.
- **Q4 (ok):** unknown `rules` keys: C6 P14 kept (keys outside the CLI's namespaces are checked only when the module declares `rules`), strengthened: keys in a CLI-reserved namespace are always checked against the CLI's table. Changes D176.
- **Q5 (ok, option A):** a collection's node has `representation: 'collection'` (open union); its `path` is virtual and its members are the distinct `items[].file`. Rejected: a `collection?: true` flag. Changes D178.
