# C3 plan review (with super-plan, C1, C2 consistency): fresh-eyes triage

A clean-context agent reviewed REQUIREMENT.md, AGENTS.md (D1–D88), the super-plan (R2 pending), the earlier reviews, C1 (A1, A2), C2 (B1 pending) and the C3 draft (round 4). It verified three claims on the web: CSS Cascade 6 (specificity is compared before scope proximity; a nested `@scope` prelude is relative to its parent; selectors inside `@scope` take no specificity from the prelude); Firefox 146 shipped `@scope` on 2025-12-09 (MDN flags nesting inside `@scope` as varying by engine); Vite's default `build.cssTarget` (chrome111, firefox114, safari16.4) is below CSS nesting support, so Lightning CSS lowers nesting by default.

It reported 45 findings (G1–G45). Status: **resolved** (C3 round 5).

**Outcome.** Instead of patching the region/`@scope` design (G1, G2, G3, G9, G23, G31, G32), the user redefined the showcase styling requirements: the **shell lives in a shadow root, showcases are isolated light-DOM content** receiving a colour scheme (D89; D44 tiers 2–3 and D87 superseded). That makes those findings moot. Group B: G2/G3 resolved by D89; **G10:** no browser testing; acceptance 4 and 8 became review guidelines, and the contrast test and helper were dropped (D85 revised); **G12:** `:where(.tss-shell[data-theme])` wrapper plus per-class property ownership; **G25:** D86 rule 4 amended (now rule 3: modules may use own-prefixed arrangement-only classes). Group A applied, adapted to the new design (e.g. G5's at-rule handling now also moves `@font-face` into a separate fonts stylesheet, because `@font-face` doesn't work inside shadow roots; G24 moot because the shell is rendered by JavaScript).
