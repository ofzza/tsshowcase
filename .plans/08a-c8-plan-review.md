# C8 plan review triage (round 2 draft)

> Two fresh-eyes reviews of the C8 round-2 draft (2026-10-19), run in parallel by clean-context agents: **W** = a whole-project consistency review (all plans, not focused on C8; 21 findings), **C** = a C8-focused review (the plan and its proposed amendments; 26 findings, with experiments on TypeScript 5.0.4 and 6.0.3). Findings are merged below as U1–U23. Status: **triaged; group A on hold** while the user redefines the unit/group concepts (2026-10-19: "what gets a menu item and what gets a page", instead of what *is* a unit or group); group B is applied with the plan's round 3 unless the user objects.

## Verified or rejected

- **W10 rejected:** "TS 7's `exports` blocks `typescript/package.json`" is wrong: `npm view typescript@7 exports` lists `"./package.json"` (checked in this session; C also verified it).
- **C8 verified:** `getAliasedSymbol` throws on non-alias symbols (`export *` members, the entry's own declarations).
- **C9, C10 verified:** `export * as ns` resolves to the barrel's `SourceFile`; `export = obj` gives no exports; module augmentations add declarations in other directories; a named default function has `symbol.name === 'default'`; return types print as `Element` unless fully qualified.
- **C26:** `@typescript/typescript6@6.0.2` is a thin wrapper over `@typescript/old` (`npm:typescript@^6`, currently 6.0.3): the analysed version floats within 6.x. Wording only.

## Group A: decisions for the user

| # | Sources | Finding | Recommendation |
| - | ------- | ------- | -------------- |
| U1 | W9, C4 | **"Own directory" is gone.** Under D153, `components/Button.tsx` + `components/Card.tsx` silently become one unit `components`; a flat `src/` library is one unit. REQUIREMENT: "Be located in its own directory". | A rule `react/own-directory` (error): a unit with **more than one public component or hook declared in different files**, unless the unit has a directory config (which acknowledges the grouping). The headless split (one component, one hook) and a flat library with a `src/.tsshowcase` both pass. |
| U2 | W1 | **Unexported units go unreported.** A directory with `NewThing.tsx`, README, tests and a showcase but no entry export becomes a group (or is ignored). D21's "exported from the entry" has no implementation since the orphan-showcase rule went away. | A warning `react/unexported-source`: a group with **no units below it** whose (non-test, non-showcase) source files declare exports. Internal helper directories without a README or showcase aren't groups (U3), so they don't trigger it. |
| U3 | C11, C25, W4a, W15 | **Groups catch too much.** With `unitRoot` = the package directory, `.changeset/README.md`, `docs/`, `scripts/` become group pages; `unitRoot` itself would be a group ("src" menu level); a kinds-only or claim-only config creates a group page. | Tighten D157: a group is a non-unit directory **strictly below** `unitRoot` that has **units below it or showcase files**; its README (if any) is its page. A README alone, or a directory config alone, doesn't make a group. A directory config that ends up neither unit nor group gets the "applies to nothing" warning (refines R2-1). `unitRoot` is never a group. |
| U4 | W11, W12, C13 | **Claim semantics.** (a) The key `scope` means the scan boundary at the top of the config and claims inside `units` maps. (b) A display-only config (`name`, `order`, `showcase`) on a subdirectory an ancestor claims silently splits it into its own unit. (c) An ancestor claim passes through a nearer config that doesn't claim the file (`Ghost/parts/Icon.tsx` skipping Ghost's config to Buttons' `variants/**`). (d) Pattern semantics undefined (files vs directories, negations, dotfiles, escaping `[id]`/`(group)` when made repo-relative). | (a) Rename the key to **`claims`**. (b) A directory is explicitly a unit only when its config has **`claims`** or **`unit: true`** (a new key); display-only configs never change structure. (c) A config with `unit: true`/`claims` is a **barrier**: ancestors' claims never reach through it. (d) Patterns match the declaring file's path relative to the config's directory (picomatch, `dot: true`, no negations in v1; `parts/**` for a subtree); stored with their base directory, never rewritten. |
| U5 | W6, C18 | **Claimed subdirectories vs files.** Tests, showcases and READMEs in a claimed subdirectory don't count for the claiming unit (tests miss `react/test-required`, showcases turn the subdirectory into a nested group). | Claimed subdirectories that hold no units of their own **belong to the claiming unit**: their tests count, their showcase files are the unit's showcases, they are never groups, and `verify` treats them as part of the unit (ignored as directories). C10's test mapping already matches by prefix. |
| U6 | W3a, C12a | **`showcase: false` and routes.** A hidden unit still needs a route (C2: unit targets must resolve), and README links point to a page that isn't presented. | `resolveRoute` may return `undefined` for unit and group targets with `showcase: false`; the route stays unset; C5 maps links to them like route-less groups (VCS host). C2 B9 + a **C5 amendment**. |
| U7 | C9 | **Namespace re-exports and `export =`.** `export * as utils from './utils/index.js'` resolves to the barrel file: one unit at `src/utils`; `export = obj` yields no exports. | `export * as ns`: one unit at the barrel's directory (kind from the namespace's members, by the usual order), members' own directories are not units (documented). `export =`: a `react/export-equals` warning ("CommonJS-style exports aren't analysed") and no units from that entry. |
| U8 | C16a | **`init` with no resolvable entry** (a fresh package): nothing to append the export to. | `scaffold` throws a clear error ("no entry found; add `exports`/`main`, or set `entries`") rather than inventing an entry file. |
